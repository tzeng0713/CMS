# 收費清單管理（Charge List）已知缺漏 / 待辦事項

本次功能已完成查詢、新增、修改、匯出圖片的核心流程，並通過後端 `mvn compile`、前端 `ng build` 與 curl 手動 API 驗證。以下是尚未完成或刻意簡化、需要後續處理的部分。

## 1. 業務邏輯尚未串接

- **收租管理／退款管理回寫 `status`**：目前 `status`（1=已結清 / 2=未結清）只能由其他模組回寫，但實際回寫邏輯完全沒有實作，本次刻意排除（使用者已確認「之後再處理」）。
  - 且目前專案並沒有獨立的「收租管理」模組，只有 `rent_payments`（租金繳交紀錄），語意上最接近但沒有 `charge_list_id` 關聯欄位，未來要接上這條回寫邏輯前，需要先確認 `rent_payments` 是否要補這個欄位。
  - `refunds` 表已經有 `charge_list_id` FK（既有 migration 加的），但退款完成後回寫 `charge_lists.status` 的程式碼同樣沒有實作。

## 2. 公司抬頭 / 銀行資訊

- 銀行資訊（分行/戶名/帳號）已改為從租約對應的辦公室 → 分館（`branches.bank_branch` / `bank_account_name` / `bank_account`）讀取，不再是前端寫死常數。若某分館尚未在「分館管理」填寫銀行資料，匯出圖片會顯示「-」。
- **AFW Logo 圖示**：已於 `.charge-list-print-area` 加入 `<img src="assets/afw-logo.png">`，圖檔本身由使用者自行放入 `frontend/src/assets/afw-logo.png`（不在版本控制的程式碼變更範圍內）。

- 補充說明：匯出圖片上的「合計」刻意加總租約租金（`contract_rent + total_amount`），這個加總**只存在於匯出圖片**，資料庫 `total_amount` 欄位與列表頁「收費總金額」都維持不含租金，這是確認過的設計，不是缺漏。

## 3. 篩選功能的簡化

- 「租約」查詢條件目前是直接輸入**租約編號（數字)**，不是像客戶一樣先模糊搜尋再選擇。原因：系統目前沒有現成的「依關鍵字查租約」元件可以重用，做一個真正好用的租約查找需要額外開發。

## 4. 權限控管尚未加上

- 其他模組（例如租金管理）有 `canCreateRent`/`canEditRent` 這類依角色權限顯示/隱藏按鈕的機制，但本次收費清單的「新增」「修改」「匯出圖片」按鈕**對所有登入角色一視同仁**，沒有加上任何角色限制。原始需求沒有明確要求限制，但如果之後想比照其他模組做角色管控，需要另外定義規則（例如是否只有主管/督導秘書能開單）。

## 5. 測試覆蓋

- **沒有新增任何自動化測試**（無論後端 JUnit 或前端元件測試）。
- 既有的 `CmsApplicationTests.java` 測試套件目前在本機環境完全跑不起來（`ApplicationContext` 載入失敗），這是跟本次改動無關的既有環境問題，但也代表沒有回歸測試網可以驗證本次新增的程式碼。
- 所有驗證都是透過 `curl` 直接打 API 與 `ng build`/`mvn compile` 完成，**沒有使用瀏覽器實際操作過** UI（篩選、下拉選單、編輯側欄、匯出圖片按鈕、預覽視窗），因為環境內沒有可用的瀏覽器自動化工具（`chromium-cli` 不存在）。
- 分頁功能只用 1 筆測試資料驗證過 API 回傳格式正確，**沒有實際測試超過一頁（>20 筆)時「上一頁/下一頁」按鈕與頁碼顯示是否正確**。

## 6. 其他

- 沒有實作刪除／作廢功能（比照專案內其他模組都沒有 delete，屬於一致的既有慣例，非本次遺漏，僅供記錄）。
- RWD（窄螢幕）版面只套用了既有的 CSS breakpoint class，沒有實際在小螢幕裝置或縮小視窗下驗證顯示效果。
