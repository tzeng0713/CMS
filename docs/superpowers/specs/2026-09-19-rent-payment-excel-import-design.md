# 新增對帳 Excel 匯入設計

日期：2026-09-19  
狀態：待使用者審閱

## 目標

保留既有頁面名稱「新增對帳」，將現有單筆輸入流程改為 Excel 匯入、預覽檢核與一次新增多筆對帳資料。使用者不需逐筆輸入；任何一列未通過檢核時，本次匯入不得寫入資料庫。

## 第一版 Excel 格式

只接受 `.xlsx` 檔案，讀取第一個工作表。第一列必須包含下列欄位名稱；欄位順序可不同，其他欄位會忽略：

| 欄位名稱 | 格式 | 必填 | 用途 |
| --- | --- | --- | --- |
| 公司名稱 | 文字 | 是 | 以修剪前後空白後的完整公司名稱，精確比對既有客戶。 |
| 租金月份 | `YYYY-MM` | 是 | 儲存為既有的 `YYYYMM` 月份值。 |
| 繳款日期 | `YYYY-MM-DD` 或 Excel 日期儲存格 | 是 | 對帳繳款日期。 |
| 費用起日 | `YYYY-MM-DD` 或 Excel 日期儲存格 | 否 | 費用期間起日。 |
| 費用迄日 | `YYYY-MM-DD` 或 Excel 日期儲存格 | 否 | 費用期間迄日。 |
| 金額 | 大於 0 的數字 | 是 | 本次繳款金額。 |
| 收據號碼 | 文字 | 否 | 收據識別資訊。 |
| 備註 | 文字 | 否 | 補充說明。 |

第一版以既有頁面欄位作為匯入格式；未來欄位有變動時，應只調整欄位對應與檢核規則，不改變「上傳 → 預覽 → 確認新增」的流程。

## 客戶與租約對應

1. 公司名稱僅作精確客戶比對，不採用模糊搜尋，也不以負責人、統編或其他欄位猜測，避免資料寫入錯誤客戶。
2. 查無客戶時，該列標示「找不到客戶」。
3. 對應客戶沒有租約時，該列標示「客戶沒有可對應的租約」。
4. 對應到客戶後，採用該客戶目前既有單筆新增流程使用的最新租約（contract id 最大者）。此規則使 Excel 匯入與既有新增行為一致。

## 檢核與寫入規則

上傳後，後端完整解析但不寫入資料庫，並逐列檢核：

1. 檔案副檔名、檔案大小不超過 10 MB、資料列不超過 1,000 列。
2. 必要欄位名稱均存在，且第一個工作表至少有一筆資料。
3. 必填值、月份、日期及金額格式正確；費用起日不得晚於費用迄日。
4. 公司名稱能精確對應一名客戶及其最新租約。
5. 同一 Excel 內若出現完全相同的「公司名稱、租金月份、繳款日期、金額、收據號碼」組合，後出現的列標示為重複資料。
6. 若資料庫已有相同的「客戶、租金月份、繳款日期、金額、收據號碼」組合，該列標示為已存在的對帳資料。

檢核結果會以逐列文字顯示，不只依賴顏色。只要任一列有錯誤，確認新增按鈕維持停用；使用者需修正原 Excel 後重新上傳。確認新增時，後端會再次執行相同檢核，並使用單一交易寫入所有列；任何列失敗即全部回復，不會產生部分匯入。

## 使用者介面

頁面維持既有導覽與「新增對帳」名稱。此次不重做系統整體視覺：既有側欄、頁首、字體、暖白底、深灰文字、金色主要按鈕、細框表格與右下角提示位置均維持不變。

參考畫面只採用其內容排版與資訊層級：匯入區、匯入摘要、對帳預覽表與底部動作列。這些新區塊會直接沿用現有查詢對帳／查詢客戶頁面的 panel、表格、分頁器與按鈕樣式，而非引入新的全頁配色、側欄圖示或設計系統。

初始狀態只顯示「匯入 Excel」區塊：

- 白底描邊按鈕「選擇 Excel 檔案」，接受 `.xlsx`。
- 未選檔時不顯示預覽表或新增按鈕。

成功解析後，畫面依序顯示：

1. 已選檔名與「重新選擇」按鈕。
2. 摘要：共 X 筆、可新增 Y 筆、需修正 Z 筆；錯誤筆數以文字及紅色提示。
3. 風格與查詢對帳一致的預覽表：列號、公司名稱、租金月份、繳款日期、金額、收據號碼、備註、檢核結果。
4. 表格每頁 20 筆，可換頁；窄螢幕允許表格水平捲動。
5. 頁面底部動作列：左側「清除本次資料」，右側金色「新增 Y 筆對帳」。有錯誤時右側按鈕停用，旁邊說明「請先修正 Z 筆資料」。

清除、重新選檔及再次進入新增對帳頁面，都會清空暫存預覽與錯誤狀態。上傳、解析、寫入進行中，相關按鈕會停用並顯示處理狀態。完成後顯示右下角淡入淡出的成功或失敗提示，並導向查詢對帳頁面重新載入結果。

## 前後端介面

新增兩個端點，既有單筆 `POST /api/rent-payments` 保留，避免影響其他既有流程：

1. `POST /api/rent-payments/import-preview`
   - `multipart/form-data`，欄位名稱為 `file`。
   - 回傳檔名、總筆數、有效筆數、錯誤筆數及每列已正規化資料與檢核訊息。
   - 不寫入資料庫。
2. `POST /api/rent-payments/import`
   - JSON 內容為預覽的來源欄位與操作人 id。
   - 後端不信任前端傳入的客戶／租約 id，會以公司名稱重新解析並再驗證。
   - 成功時回傳新增筆數；失敗時不新增任何資料。

前端新增 API 型別與呼叫方法，將既有新增對帳區塊改成上傳控制、摘要、預覽資料與批次確認動作。後端新增專責的匯入服務，負責 Apache POI 解析、欄位正規化、客戶／租約對應、檢核與交易寫入；現有 `RentPaymentService` 繼續負責一般對帳查詢與單筆新增／修改。

## 測試與驗收

後端測試至少涵蓋：正確 Excel 預覽、不支援檔案、缺少標頭、格式錯誤、找不到客戶、重複資料、確認匯入全數成功、確認匯入時其中一列失敗會全部回復。

前端測試至少涵蓋：初始上傳狀態、預覽摘要與逐列錯誤呈現、有錯誤時確認按鈕停用、清除後回到初始狀態、成功匯入後導向查詢對帳。

驗收標準：使用者可以用一份含多筆資料的 `.xlsx`，在不直接寫入資料庫的前提下查看每列檢核結果；當所有列均有效時，按一次按鈕即新增全部對帳資料；任何一列有問題時不會新增任何資料。

## 非目標

第一版不提供 Excel 欄位自訂映射、預覽列表內直接編輯、部分成功匯入、`.xls`／`.csv` 支援，或下載範本功能。
